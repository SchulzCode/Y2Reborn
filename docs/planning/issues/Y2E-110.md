# Y2E-110 — Reconcile stock scatter and runtime partition metadata

## Goal
Produce a partition map that explicitly reconciles package address conventions with the current device's readable metadata.

## Why
The stock scatter distinguishes linear and physical addresses and eMMC regions. Guessing a block node or offset would invalidate backups and risk later writes.

## Dependencies

- Y2E-101: https://github.com/SchulzCode/Y2PlayerNative/issues/1 (evidence review required)
- Y2E-105: https://github.com/SchulzCode/Y2PlayerNative/issues/2 (evidence review required)

Y2E-101 and Y2E-105 reviewed; authorized non-root target unchanged. Unavailable runtime metadata must remain a blocker, not be replaced by package guesses.

## Evidence / Assumptions
`OriginalFirmware/MT6582_Android_scatter.txt` SHA-256: `e5fe03e9f3219cc9b5ead27892f2ddb722acc16adce3306d27feb87893cd977e`. In this package BOOTIMG is linear `0x3180000`, physical `0x1d80000`, size `0x1000000`; PRELOADER is EMMC_BOOT_1. These values are reference observations, not approved read/write coordinates. `reverse/ramdisk/fstab` uses vendor /emmc@ aliases and protect partitions.

## Scope
Map metadata only, including calibration candidates and unresolved address translation.

## Out of Scope
No dd/cat of block-device contents, block ioctls, mounting, unmounting, filesystem repair, scatter editing, PMT repair, readback or flashing.

## Expected Files / Components
`docs/knowledge/partition-map.md`, `docs/knowledge/partition-map.tsv`; private raw metadata capture.

## Instructions
1. Read the exact cataloged scatter as text and reference ramdisk fstab/init mount lines. Include every scatter entry, even non-download, zero-size or sentinel entries.
2. With Y2E-105 capture rules, run separately: `cat /proc/partitions`, `cat /proc/dumchar_info`, `cat /proc/emmc`, `cat /proc/mounts`, `ls -l /dev/block`, `ls -l /dev/block/platform`, `ls -l /sys/class/block`, `ls -l /emmc@*`. Failure is valid evidence. Follow only the observed platform directories to inspect their by-name symlink listings; no recursive device opens.
3. For each observed mmc block/partition name, read only corresponding `/sys/class/block/<name>/dev`, `start`, `size`, and `uevent` if present. Record permissions and missing files. Treat sysfs block counts as 512-byte sectors; retain raw counts and annotate converted bytes, independently cross-checking another source. Do not equate these with physical-block-size values.
4. Table columns: region, scatter name, runtime alias/node and major:minor, linear offset, region-relative physical offset, runtime start/count with units, normalized byte range, package file/hash/type, download flag, mount/use, possible personalized data, confidence/evidence.
5. Explicitly discuss MBR/EBR layout versus runtime numbering, eMMC boot hardware regions versus EMMC_USER and SD, the scatter linear/physical offset difference, and FAT/BMTPOOL variable/sentinel semantics. Check normal fixed ranges for overlap and region bounds. Leave unresolved entries UNKNOWN.
6. List NVRAM, PRO_INFO, PROTECT_F, PROTECT_S, SECCFG, MISC and any newly observed calibration partitions as candidates for later assessment. Do not assume all contain calibration or that a package's SEC_RO replaces device-specific data.

## Acceptance Criteria
- [ ] Every scatter entry is accounted for; address domains and units remain distinct.
- [ ] Runtime mappings have direct evidence or explicit missing/conflicting evidence.
- [ ] Normal ranges are independently cross-checked; unresolved/sentinel entries are not assigned guessed readback ranges.
- [ ] Packaged images are distinguished from full partition lengths and personalized partitions with no supplied image.
- [ ] Report concludes whether precise backup coordinates can yet be approved; it contains no executable readback/flash recipe.
